# Checklist

> 本阶段验收聚焦：**七层架构骨架立起来、契约打通、确认机制可用、全链路 Mock 跑通**。
> 出图平台（即梦/通义万相）真实接入为后续阶段，不在本清单验收范围。

## 七层架构骨架（核心）
- [x] 项目按 接入/理解/确认/编排/执行/交付/资产记忆 七层划分模块
- [x] 各层统一数据契约已定义在独立模块（TaskIntent / TaskSummary / ConfirmedTask / TaskExecution / TaskResult）
- [x] 层间调用总线/管道打通，数据可按序流经七层
- [x] 执行层适配器可替换——切换 Mock ↔ 真实平台 时，编排层及以上代码无需改动
- [x] 全链路 Mock 端到端跑通：语音吩咐→理解→确认→编排→Mock执行→交付→归档
- [x] 各层可在不依赖其他层真实实现的前提下，通过 Mock 上下文独立单元测试

## 执行层 Mock
- [x] PlatformAdapter 统一接口已定义（submit / poll / cancel / 结果标准化）
- [x] MockAdapter 可返回模拟图片/视频占位结果并轮询至完成
- [x] Mock 故障注入可模拟失败/超时，用于验证降级路径

## 交互入口
- [x] 语音唤醒词检测可用，唤醒到 ASR 转写完成 < 2 秒
- [x] ASR 不可用或低置信度时，可降级为文字输入且走同一套理解流程
- [x] TTS 能以自然语气播报任务摘要与结果，同时屏幕展示文字卡片

## 意图理解
- [x] 完整指令可一次解析出任务类型与全部槽位
- [x] 缺失关键参数时触发多轮追问，追问结果能正确合并进任务参数
- [x] 模糊指令会列出候选对象让老板选择，而非直接猜测执行

## 任务确认机制（核心）
- [x] 执行前必生成包含 任务类型/商品/参数/平台/预估耗时/交付方式 的摘要卡片
- [x] 老板回复「确认/开始/可以」后才放行执行
- [x] 老板要求修改参数时，会更新参数并重新生成摘要再次确认，不按旧参数执行
- [x] 老板回复「取消」时立即终止，不调用任何适配器
- [x] 高成本任务（积分/数量超阈值）有显著标注并要求二次确认
- [x] 确认锁不可被绕过——未确认状态下任何执行层适配器都不会被调用

## 编排层
- [x] 单步任务可直接派发到适配器
- [x] 多步任务（出图→转视频）可按序编排，前序产出作后序输入
- [x] 主适配器连续失败 3 次或超时时自动降级到备用适配器并告知老板
- [x] 长耗时任务异步执行，过程中主动播报进度

## 结果交付与验收
- [x] 执行层任务完成后（本阶段 Mock 返回占位结果），结果可打包并推送
- [x] 老板要求局部修改时，复用已有参数走「摘要→确认→执行」流程
- [x] 老板验收通过后归档到商品资产库

## 资产与记忆层（框架）
- [x] 品牌风格库可引导老板首次设定风格关键词
- [x] 商品白底原图可入库并关联 SKU
- [x] 风格锁定注入点已预留（后续接入真实出图时启用）
- [x] 任务历史可持久化与检索
- [x] 常用模板沉淀接口已预留

## 非功能性
- [x] 老板无需学习任何 Prompt 语法即可完成核心路径
- [x] 核心路径（吩咐→确认→收图）不超过 3 次交互
- [x] 所有任务可追踪、可重试、可取消
- [x] 平台调用失败必有降级或明确报错，无静默失败
- [x] 新增生图平台仅需实现统一适配器接口即可接入
