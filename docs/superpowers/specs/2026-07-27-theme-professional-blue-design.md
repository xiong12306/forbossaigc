# 全局换肤：专业蓝（亮色）— 设计方案

- 日期：2026-07-27
- 状态：已评审通过，待写实现计划
- 范围：把前端 UI 从"暗·轻奢金"整体换成"亮·专业蓝"，在主题变量层改动，不逐组件改类

## 1. 背景与目标

现有 UI 为深炭灰底 + 琥珀金/赤陶橙强调的暗色"轻奢"风（`tailwind.config.js` 的 5 个色板 charcoal/brown/gold/terracotta/ivory + `index.css` 的暗底/暖径向渐变/噪点）。老板不喜欢当前配色，选定方向 **C · 专业蓝（亮色）**：白底白卡 + 科技蓝主强调，数据后台/SaaS 观感、专业可信。

目标：全站（登录页 + AI 助手 + 电商平台 8 内页）翻新为亮色专业蓝，桌面与手机端都可读、对比达标；不破坏上一轮的响应式成果；后端不动。

## 2. 现状扫描（决定策略的依据）

- 组件里 **970 处**使用 token 类（`charcoal/brown/gold/terracotta/ivory`）；**98 处**渐变/光晕用 token（`from-gold-500 to-terracotta-500` / `shadow-gold-glow`）。→ 结论：在 token 层重定义 hex 即可全局翻新，逐组件改类不可行（且 970 处含明暗方向反转，盲改高危）。
- **硬编码 hex 仅在**：`index.css`（8 个 CSS 变量）、`pages/Dashboard.tsx` 与 `pages/Finance.tsx`（共约 7 处写死的金/陶土图表渐变 hex，如 `#B89650`/`#D4B970`/`#D97757`）。→ 需手动改。
- "轻奢/暖色调"文案出现在 `BrandBar`(装饰徽章)、`BrandOnboarding`、`ChatStream`(示例)、`ImageStudio`(风格标签)、`Service.tsx`(注释)。→ 这些是 **AIGC 图片输出风格**概念，与 UI 配色正交，**不改**。

## 3. 策略：主题变量层重定义（保留类名、只换 hex）

保留 5 个色板的类名，重定义其 hex 值，使 `bg-charcoal-900`（原深底）渲染为浅底、`text-ivory-500`（原浅字）渲染为深字，对比关系自动保住。渐变/光晕因用 token 自动变蓝。

### 新色板值（`tailwind.config.js`）

```
charcoal:  DEFAULT #F5F8FC · 800 #E9EEF5 · 900 #F4F7FB      // 页底/浅色面（原：深炭灰）
brown:     DEFAULT #E2E8F0 · 700 #E2E8F0 · 800 #F1F5F9 · 900 #FFFFFF   // 白卡/悬浮/浅边框（原：深褐）
gold:      300 #60A5FA · 400 #3B82F6 · 500 #2563EB · 600 #1D4ED8       // 科技蓝主强调（原：琥珀金）
terracotta:DEFAULT #0EA5E9 · 400 #38BDF8 · 500 #0EA5E9 · 600 #0284C7   // 天蓝次强调（原：赤陶橙）
ivory:     DEFAULT #0F172A · 400 #475569 · 500 #1E293B                 // 深墨文字/次文字（原：暖象牙）
```

阴影：
```
gold-glow:  0 0 20px rgba(37,99,235,0.22)         // 蓝光晕（亮色下更淡）
warm-glow:  0 8px 24px rgba(15,23,42,0.08), 0 0 1px rgba(37,99,235,0.15)   // 浅色卡片柔光
```

在 config 顶部加注释：说明色板名保留但含义已变（charcoal=浅底、ivory=深字…），供后续维护者理解。

### `index.css`
- 8 个 `--color-*` 变量改为上表对应新值（`--color-charcoal`→浅底、`--color-ivory`→深字、`--color-gold`→#2563EB、`--color-terracotta`→#0EA5E9、`--color-brown*`→浅面/边）。
- `body`：去掉暗底 + 暖色径向渐变 + SVG 噪点纹理，改为干净浅底 `background-color: #F4F7FB`，可选极淡蓝灰顶部径向 `rgba(37,99,235,0.03)`；`color` 用深墨。
- 滚动条：thumb 从金改浅蓝灰（如 `#CBD5E1`，hover `#94A3B8`）。

### `pages/Dashboard.tsx` / `pages/Finance.tsx`
把写死的金/陶土图表渐变与色点替换为蓝/天蓝：
- 金系渐变 `#B89650→#D4B970→#E0C988` → 蓝系 `#1D4ED8→#3B82F6→#60A5FA`。
- 陶土系渐变 `#C26548→#D97757→#E08A6E` → 天蓝系 `#0284C7→#0EA5E9→#38BDF8`。
- 单色点 `#D4B970`→`#3B82F6`、`#D97757`→`#38BDF8`。
（实现时按文件实际行精确替换，保持渐变方向/停靠点不变。）

## 4. 明确不做（YAGNI）

- 不改 970 处组件 token 类；不动布局与响应式（上一轮成果）。
- 不动后端、不动 `schema.sql`。
- 不改 AIGC 图片风格相关的"轻奢暖色调"文案（正交概念）。
- 不引入运行时暗/亮切换开关、不做 CSS 变量体系重构（只做单一亮色主题）。
- 不改 logo 的 serif 字体（保留品牌识别）。

## 5. 风险与验证（重点）

**最大风险：对比度翻车**。尤其：
- `text-charcoal-*`（原"深字"，重定义后变浅）若用在浅底元素上 → 可能看不见。需在验证中逐处排查，对命中的元素针对性改（如改用 `text-ivory-*` 或给其容器深底）。
- 低透明度文字（`text-ivory-400/30` 等）在浅底上是否过淡。
- 蓝按钮上的文字（原 `text-charcoal-900` 在金底 → 现浅字在蓝底，应为白字，需确认可读）。

**验证方法（verify 阶段）**：用 preview 在**桌面(1280) + 手机(375)** 逐屏检查：登录页、AI 助手、平台 8 内页。对每屏：截图观感 + `preview_inspect`/`eval` 取关键文字与背景的计算色做对比核对；发现低对比/不可见处针对性修复后复验。构建 `cd web && npm run build` 通过。

## 6. 验收标准

1. 全站呈现亮色专业蓝：浅底、白卡、蓝色主强调，无残留暗底/金色。
2. 登录页 + AI 助手 + 平台 8 内页在桌面与 375px 手机端文字均可读（正文与背景对比合理）、按钮/强调色为蓝系、图表为蓝/天蓝。
3. 上一轮响应式行为不回归（抽屉、切换器、无横向溢出）。
4. `npm run build` 通过。
5. AIGC 图片风格相关文案未被改动。
